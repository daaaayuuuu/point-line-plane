# 八阶段前端开发文档

## 总体结构

Web 端采用类似扣子工作台的双栏结构。左侧固定导航从上到下依次呈现品牌 Logo、当前产品空间、整体进度、“我的项目”、第 1 步到第 8 步的完整产品生产流程，以及底部的个人中心和退出入口；右侧在同一工作台内切换项目列表或当前步骤内容，不再跳转到另一套页面框架。已完成步骤可以回看，当前步骤突出显示，未来步骤可以预览，但不能绕过后端确认、授权和阶段条件执行。

创建新产品采用非遮罩式气泡卡片引导：先用小型工作台示意解释创建入口和后续流程，再在同一张卡片中填写产品名称与想法。用户可以随时关闭或返回，不会被全屏弹窗打断。

每一步保持相同的信息顺序：本阶段目标、AI 正在处理的工作、可视化成果、用户需要做的决定、可折叠的技术依据。移动端通过顶部按钮打开纵向八步路线。

| 阶段 | 用户看到的名称 | 主要前端能力 | 对应后端能力 |
| --- | --- | --- | --- |
| M1A | 需求与方案 | 回答补充问题、预览 PRD/方案、确认或退回修改 | 项目、需求问答、Artifact、确认与 Revision |
| M1B | 产品地图 | 产品图谱、关键决策、虚拟用户走查、问题清单 | Graph、Decision、Simulation、Finding |
| M1C | 自动开发 | 开发任务、隔离空间、受控工具、代码文件与版本 | Task、Workspace、ToolRun、CodeFile、Version |
| M1D | 测试与预览 | 自动测试、有限修复、真实预览、反馈改版与验收 | Quality、Repair、Preview、Feedback、Acceptance |
| M2A | 额度与模型 | 额度、用量、费用、Key 连接与撤销 | Quota、Usage、CostAuthorization、Credential |
| M2B | 授权与部署 | 云凭证、费用确认、部署、状态与回滚入口 | DeploymentAuthorization、Deployment、CloudCredential |
| M2C | 完整交付 | 源码包、技术文档、测试报告、GitHub 同步 | DeliveryPackage、Download、GitHubSync |
| M3/M4 | 稳定运营 | 监控、邀请码、限流、备份与运行状态 | Metrics、Invite、RateLimit、Backup、OperationsToken |

## 关键体验闭环

1. 用户用一句产品想法创建项目。
2. M1A 通过问答补齐范围，生成并确认 PRD 与方案。
3. M1B 用可视化产品地图和虚拟用户走查，让用户在写代码前发现问题。
4. M1C 展示 AI 实际执行了哪些受控工具、生成了哪些文件，而不是只给聊天文本。
5. M1D 运行真实检查和预览，用户可以反馈并重新生成版本。
6. M2A 至 M2B 在产生费用或正式发布前明确二次确认。
7. M2C 让用户下载完整交付物；M3/M4 提供多人稳定使用所需的运营能力。

## 状态与恢复

- 首屏先检查后端健康状态，再恢复登录、项目列表和 URL 中指定的项目。
- 后台任务按固定间隔读取真实状态；刷新页面不会创造假任务。
- 空数据、未开始、执行中、成功、失败、过期和断开连接均有独立表现。
- 登录失败、后端未启动、权限不足和正式部署未启用都提供普通语言说明。

## 响应式规则

- 1440px/1280px 桌面端：296px 固定阶段导航 + 最大 1200px 主内容，业务页内部按需要使用双列或三列。
- 768px 平板端：左侧导航收进抽屉，业务双列重排为单列，主内容与辅助信息自适应。
- 390px 手机端：左侧导航使用抽屉，所有触控目标至少 44px；操作按钮保持可触达，表格和代码区域采用受控横向滚动。
- 所有正文不小于 14px，辅助信息不小于 12px；长标题、项目名、账号名使用明确的换行或省略策略，不允许逐字折行。
