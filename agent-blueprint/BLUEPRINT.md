# Agent 产品架构蓝图

> 这是一份从「需求点子 / PRD / 方向」到「可落地 Agent 产品」的架构蓝图与推导引擎。
>
> 给它一个 PRD，它负责推导出架构方案、组件选型、代码骨架，直到一个可以在真实环境运行的产品。

---

## 一、核心恒等式

一切推导的出发点只有两句话：

```
Agent = 模型（智能，已训练好） + Harness（载具，你构建的代码）
```

```
Harness = 工具 + 知识 + 观察 + 行动接口 + 权限

    工具     Tools         文件读写、Shell、网络、数据库、浏览器、业务 API
    知识     Knowledge     产品文档、领域资料、API 规范、风格指南、业务规则
    观察     Observation   git diff、错误日志、浏览器状态、传感器、指标
    行动     Action        CLI 命令、API 调用、UI 交互、消息发送
    权限     Permissions   沙箱隔离、审批流程、信任边界、审计
```

**模型是驾驶者，Harness 是载具。** 你构建的是载具，不是智能。载具因领域而变，驾驶者跨领域泛化。

---

## 二、推导流程：从 PRD 到产品（五步 SOP）

拿到一份 PRD（或一个点子、一个方向）后，按以下顺序推导。**顺序不可跳过**——每一步的产出是下一步的输入。

### Step 1：需求拆解 —— 从 PRD 提取硬事实

从 PRD 中抽取并固化以下事实，**没有的必须明确标注"待确认"**，不允许脑补：

| 维度 | 要回答的问题 |
|---|---|
| 目标 | 这个产品要完成什么？可量化的成功标准是什么？ |
| 用户 | 谁在用？人机比是多少？交互是同步还是异步？ |
| 核心闭环 | 一次完整的"输入 → Agent 行为 → 交付物"是什么？ |
| 交付物 | 最终产出是代码、文档、决策、操作，还是别的？ |
| 边界 | 明确不能做什么？（危险操作、越权数据、外部系统） |
| 约束 | 时延要求、并发量、合规、成本上限、可用的模型 |

### Step 2：领域建模 —— 把 PRD 映射到 Harness 五要素

把 Step 1 的每个事实，落进 Harness 公式的五个槽位：

```
工具     ←  交付物需要什么外部动作？（查询？写入？调用？发送？）
知识     ←  领域专长从哪来？（文档？schema？业务规则？）
观察     ←  如何确认动作产生了预期效果？（日志？diff？状态？）
行动     ←  这些动作以什么形式执行？（API？CLI？UI？）
权限     ←  哪些动作需要审批？哪些数据不能碰？
```

**产出**：一张五要素清单。这张清单就是产品的"领域骨架"。

### Step 3：组件选型 —— 查架构决策映射表

根据 PRD 特征，从第四节《架构决策映射表》中选出需要的 Harness 组件。**原则：只选需要的，不为完整而选。**

### Step 4：架构设计 —— 产出方案文档

基于前两步，产出架构方案。**铁律：无论 PRD 是否自带架构图，都必须产出一套标准化的「分层架构图」（见下方 7 层体系），不得只画一张随意的数据流图。** 方案必须包含：

1. **分层架构图（7 层）**：按下方「Agent 产品分层架构」绘制，每层标注落地锚点，并附一条贯穿各层的数据流说明
2. 工具清单（每个工具的名称、输入、输出、副作用、权限要求、归属层）
3. 系统提示词草案（身份 + 规则 + 工具说明 + 知识目录）
4. 上下文与记忆策略（会话内如何管理，跨会话如何持久化）
5. 权限与安全边界（谁能做什么，失败如何降级）
6. 可观测性设计（日志、指标、轨迹数据采集）
7. 技术栈与部署形态（单进程？服务？多 agent 团队？）

#### Agent 产品分层架构（7 层）

自上而下，每层回答一个落地问题，并对应一个落地锚点：

| 层 | 名称 | 回答的问题 | 落地锚点 |
|---|---|---|---|
| ① | 交互层 | 谁在用、怎么用？ | CLI / Web / App / API / 语音；同步 or 异步；人机比 |
| ② | 产品层 | 产品外壳是什么？ | 会话管理、请求路由、账户、业务逻辑 |
| ③ | Agent 编排层 | Harness 如何运转？ | loop、工具分发、hooks、权限、记忆、任务、技能、压缩、子 agent / 团队、目标闭环（即 s01–s17 组件选型） |
| ④ | 模型层 | 智能从哪来？ | 主模型、视觉 / 评估等辅助模型、路由、fallback、成本 |
| ⑤ | 能力集成层 | 如何触达外部世界？ | 内部工具、MCP server、知识库、第三方 API |
| ⑥ | 数据层 | 什么需要持久化？ | 记忆、任务、会话历史、轨迹数据、日志指标 |
| ⑦ | 基础设施层 | 如何部署运行？ | 单进程 / 服务 / 团队、沙箱、队列、调度、监控 |

两条**横切关注点**贯穿所有层，不单独成层：

- **安全边界**：鉴权（①）、工具审批（③）、MCP 策略（⑤）等在每一层的体现
- **可观测性**：日志、指标、轨迹数据在 ③④⑤⑥⑦ 各层的采集点

绘制方式：用 Mermaid `flowchart` 表达 7 层 + 数据流；简单需求允许某层标注「无 / N/A」，不强制每层填满。

### Step 5：代码生成 —— 从骨架到产品

**先交付方案（Step 4 的产出），经确认后再生成代码。** 代码分三层递进：

1. **骨架**：可运行的 agent loop + 3~5 个领域工具 + 系统提示词
2. **硬化**：错误处理、超时、重试、日志、配置化、权限检查
3. **产品化**：组件集成（记忆/任务/团队/MCP）、测试、部署脚本、README

## 三、PRD 分析模板（先问清这 8 个问题）

推导前，用这 8 个问题把 PRD 补完整。**答不上来的就是风险点，必须标注。**

1. **要达成什么？** 一句话说清产品目标，以及"怎样算做成"。
2. **给谁用？** 目标用户 + 使用频率 + 同步/异步交互。
3. **一次完整交付长什么样？** 从用户输入到交付物的完整闭环。
4. **需要什么外部动作？** 列出所有必须调用的系统、API、数据源。
5. **领域知识在哪？** 哪些规则、文档、schema 是模型必须知道的。
6. **什么绝对不能做？** 安全红线、数据边界、合规约束。
7. **失败怎么办？** 工具失败、模型幻觉、超时、越权时的降级策略。
8. **怎么算成功？** 可度量的指标（完成率、时延、成本、准确率）。

## 四、架构决策映射表

> 这张表是推导的核心工具：**PRD 的某个特征 → 应该选用的组件 → 生产级要点 → 参考实现。**

| PRD 特征 | 选用组件 | 生产级要点 | 参考实现 |
|---|---|---|---|
| 需要调用外部系统/API/数据源 | **工具系统** | 原子化、可组合、描述清晰；每个工具有明确副作用与权限 | s02 |
| 涉及破坏性/敏感操作 | **权限系统** | 审批管道、信任边界、操作审计、失败关闭 | s03 |
| 需要审计、拦截、埋点 | **钩子系统** | 工具前后扩展点、不侵入主循环 | s04 |
| 多步骤、需跟踪进度 | **任务规划** | 计划持久化、状态可见、断点续跑 | s05 |
| 上下文会爆、任务可并行 | **子 Agent** | 独立消息列表、最终文本回传、上下文隔离 | s06 |
| 领域知识库庞大 | **技能加载** | 目录先行、按需展开、不前置塞入 | s07 |
| 长会话、日志量大 | **上下文压缩** | 分层压缩、先裁工具结果再摘要历史 | s08 |
| 需跨会话记住偏好/决策 | **记忆系统** | 筛选→提取→整合三子系统、持久化检索 | s09 |
| 目标需持久化、断点续跑 | **任务系统** | 文件持久化、依赖图、原子状态变更 | s10 |
| 有慢操作需不阻塞 | **后台任务** | 线程执行、完成通知注入、超时清理 | s11 |
| 需定时自治触发 | **定时调度** | 持久化调度、会话级触发、幂等 | s12 |
| 多任务并行、需隔离工作区 | **Agent 团队** | 持久队友、原子认领、任务绑定 worktree、类型协议 | s13 |
| 需接入外部工具生态 | **MCP 插件** | 工具发现、命名空间、统一工具池 | s14 |
| 上述机制需协同 | **集成 Harness** | 单一循环、动态重建系统提示词、共享客户端 | s15 |
| 编排形态固定 | **工作流运行时** | 脚本拥有编排、生命周期事件、journal 续跑 | s16 |
| 需自动判断"何时算完成" | **目标闭环** | 独立判断器审查停止、目标不可能时交还用户 | s17 |

**选型原则**：从最少组件起步，宁可少选。每个组件都要回答"没有它产品会怎样"——答不上来就删掉。

## 五、生产级组件库

17 个组件按功能域分组。每个组件标注：**何时选用 / 生产级要点 / 参考实现**。

### A. 行动域（让 Agent 能动手）

- **Agent Loop**（s01）—— 一切的基础。`messages → model → tool_use → 结果 → 循环`。生产级要点：重试、超时、token 上限、`stop_reason` 完整处理。
- **工具系统**（s02）—— `TOOL_HANDLERS` 分派映射，循环不变、工具可增。生产级要点：JSON schema 严格、参数校验、错误回传格式统一。
- **MCP 插件**（s14）—— 把外部工具接进同一工具池。生产级要点：工具发现、`mcp__server__tool` 命名空间、连接失败降级。

### B. 约束域（给 Agent 划边界）

- **权限系统**（s03）—— 审批管道与信任边界。生产级要点：白名单/黑名单、破坏性操作二次确认、审计日志、默认拒绝。
- **钩子系统**（s04）—— 工具前后的扩展点。生产级要点：PreToolUse 可阻断、PostToolUse 可观察、异常不影响主循环。

### C. 认知域（让 Agent 能想清楚）

- **任务规划**（s05）—— 先计划后执行。生产级要点：计划持久化、状态流转、进度可查询。
- **技能加载**（s07）—— 按需注入领域知识。生产级要点：目录先行、正文惰性加载、版本管理。
- **记忆系统**（s09）—— 跨会话记住该记的。生产级要点：筛选→提取→整合三子系统、持久化 + 检索、冲突时用户指令优先。
- **目标闭环**（s17）—— 独立判断"何时真正完成"。生产级要点：独立评估器、目标不可能/失败/超限时交还控制权。

### D. 上下文域（让 Agent 在长任务中不迷路）

- **子 Agent**（s06）—— 隔离噪声子任务。生产级要点：独立消息列表、最终文本作为一条工具结果回传、超时回收。
- **上下文压缩**（s08）—— 上下文总会满，要有办法腾地方。生产级要点：分层压缩（先裁工具结果，再摘要历史）、保留权威指令。

### E. 协作域（让 Agent 能长期、并行地干活）

- **任务系统**（s10）—— 大目标拆小任务、持久化、依赖图。生产级要点：原子状态变更、依赖校验、磁盘持久化、并发锁。
- **后台任务**（s11）—— 慢操作丢后台。生产级要点：线程池、完成通知注入、超时与清理。
- **定时调度**（s12）—— 到点自动触发。生产级要点：持久化调度、幂等、会话级作用域。
- **Agent 团队**（s13）—— 队友分工协作。生产级要点：原子认领、任务绑定 worktree、异步邮箱、类型化协议、关停流程。

### F. 编排域（把一切组装成产品）

- **集成 Harness**（s15）—— 多机制归一到单一循环。生产级要点：动态重建系统提示词、共享客户端与模型、跨模块状态协调。
- **工作流运行时**（s16）—— 编排形态固定时写进代码。生产级要点：脚本拥有编排、生命周期事件、journal 断点续跑。

## 六、"可落地"的验收标准

一个产物只有同时满足以下条件，才算"可落地"，否则只是 demo：

1. **可运行**：一条命令能起，配置与密钥外置（`.env` / `config`）。
2. **可容错**：工具失败、模型幻觉、超时、越权都有明确降级路径。
3. **可观测**：有日志、有指标、有轨迹数据（未来微调模型的原料）。
4. **可测试**：核心循环与工具分派有单测，权限与安全有边界测试。
5. **可部署**：有明确的部署形态（单进程 / 服务 / 团队）与启动文档。
6. **可度量**：有对齐 PRD 的成功指标，并能采集。

## 七、交付方式：先方案，后代码

推导 Agent 产品时，**永远先交付架构方案，经确认后再生成代码**。方案未确认前，不写产品代码。

方案（Step 4 产出）应包含：

- 五要素清单（工具 / 知识 / 观察 / 行动 / 权限）
- 组件选型表（选了哪些、为什么、放弃了哪些）
- 分层架构图（7 层 + 数据流 + 落地锚点）
- 工具清单（名称 / 输入 / 输出 / 副作用 / 权限）
- 系统提示词草案
- 安全边界与降级策略
- 技术栈与部署形态

确认后，再按 Step 5 的三层（骨架 → 硬化 → 产品化）生成代码。

## 八、快速开始

```sh
cd agent-blueprint
pip install -r requirements.txt
cp .env.example .env   # 配置 ANTHROPIC_API_KEY 与 MODEL_ID

# 参考实现：每个组件一个可运行文件
python s01_agent_loop/code.py        # 最小 agent loop
python s15_integrated_harness/code.py  # 集成 harness 参考

# 脚手架：从模板生成新项目（见 scaffold/）
```

**推导方式**：把本文件（或其中相关章节）连同你的 PRD 一起交给 AI，要求它按第二节的五步 SOP 推导，并遵守第七节的"先方案后代码"。
